# OtpPilot

**A small, private helper for finding a fresh sign-in code in Gmail and placing it into a form when you ask.**

OtpPilot runs in your browser. It searches a few recent Gmail messages using rules you choose, checks the sender, subject and message age, then extracts a code locally. On an exact website hostname you allow, the helper can fill a blank email field when focused and fill an OTP field only after you click **Get code & fill**. It never submits the website's form.

> This repository is a starter project. It contains placeholders, not working Google credentials. You need your own Google Cloud project and OAuth client before Gmail connection can work.

## Try the visual demo

Open [`demo/index.html`](demo/index.html) in a browser. It is a local mock-up: it uses a made-up account and dummy code, makes no network requests, and does not connect to Gmail. It demonstrates the helper interaction and manual Verify step.

## What you need

- A desktop version of Chrome or Firefox.
- A Gmail account that receives the verification emails.
- A Google Cloud project with the Gmail API enabled and an OAuth client for your browser.
- Node.js 24 or newer if you want to build or run the included automated tests. There are no package dependencies to install.

## Set up your own copy

### 1. Get the code

Download this repository as a ZIP from GitHub and extract it, or clone it with Git. Keep the whole project folder together. Do not edit files under `dist/`; that folder is generated by a build and is excluded from Git.

### 2. Configure Google Cloud

1. Create a Google Cloud project you control.
2. Enable **Gmail API** for that project.
3. Open **Google Auth Platform** and configure the app name, audience and contact information. If the app is in **Testing**, add each Gmail account that will connect as a test user.
4. Create a browser-specific OAuth client as described below. Use only the client ID in source configuration; never commit a downloaded credentials JSON or a client secret.

Google classifies `gmail.readonly` as a restricted scope. Testing projects may show an unverified-app warning and their Gmail authorizations can expire after seven days. Wider distribution may require Google's verification. See the [Google OAuth docs](https://developers.google.com/identity/protocols/oauth2/) and [Gmail scope guidance](https://developers.google.com/workspace/gmail/api/auth/scopes).

### 3. Choose Chrome or Firefox

#### Chrome

1. In Chrome, open `chrome://extensions`, turn on **Developer mode**, and choose **Load unpacked**. Select this project folder. This first load lets you see the extension's ID.
2. In Google Cloud, create an OAuth client with application type **Chrome Extension**. Enter the extension ID shown at `chrome://extensions` as the **Item ID**.
3. Copy the resulting client ID into `manifest.json`, replacing `YOUR_EXTENSION_OAUTH_CLIENT_ID.apps.googleusercontent.com`.
4. Reload OtpPilot from `chrome://extensions`.

The extension ID can change if the unpacked extension is loaded from a different location or installation. If it changes, update the Chrome OAuth client setup to match.

#### Firefox

1. Open `manifests/manifest.firefox.json` and replace the sample `browser_specific_settings.gecko.id` with a unique ID you control. For example, use a UUID in braces or an email-shaped ID under a domain you control. Do not submit the sample `@example.invalid` ID to AMO.
2. In Google Cloud, create a separate OAuth client with application type **Desktop app**.
3. Replace `YOUR_FIREFOX_DESKTOP_CLIENT_ID.apps.googleusercontent.com` in `src/shared/firefox-oauth-config.js` with your Desktop app client ID.
4. Run `npm run build:firefox`.
5. In Firefox, open `about:debugging#/runtime/this-firefox`, click **Load Temporary Add-on…**, and select `dist/firefox/manifest.json`.

Firefox generates and uses its loopback OAuth callback automatically. You do not need to paste the callback URL into Google Cloud. If the token exchange requests a client secret, enter the `client_secret` value from your local Desktop app credentials in OtpPilot Settings. The extension does not need the credentials JSON itself.

### 4. Connect your Gmail account

1. Open OtpPilot **Settings**.
2. Enter the Gmail address that receives the codes. Enter the exact sender address, a distinctive subject phrase, code length, and freshness window for your email provider.
3. Add or edit the OTP patterns. A pattern must contain exactly one capture group around the code. For example, `Your sign-in code is ([0-9]{6})` matches a six-digit code after that phrase. Keep the surrounding text specific enough to avoid picking another number from the message.
4. In **Supported websites**, enter exact HTTPS hostnames, one per line, such as `login.example.com`. Saving asks the browser for access to only those hostnames.
5. Open the popup, choose **Connect Gmail**, and approve read-only access for the same account entered in Settings.
6. Use **Find latest code** to retrieve a code. The popup lets you reveal and copy it.

### 5. Use the optional website helper

On an allowlisted page, focusing a blank email-type field fills it with the configured Gmail address. For an OTP field, click **Get code & fill** beside the field. Review the filled field and submit the website yourself. The extension does not automatically submit forms.

The helper only runs on exact HTTPS hostnames that you explicitly allow and grant. Remove a site from Settings to remove the helper permission. Some websites use separate boxes for each digit; those forms may need you to paste the code from the popup instead.

## Build and test

Run these commands from the project folder:

```text
npm test
npm run build:chrome
npm run build:firefox
npm run package:firefox
```

The Firefox command creates `dist/firefox/`. The package command creates three archives under `dist/releases/`: a temporary Firefox package, an AMO upload ZIP, and a source archive. Before submitting to Mozilla, set a unique Gecko ID and the correct Firefox OAuth client ID. Mozilla must sign an add-on before standard Firefox can install it permanently. See [`docs/AMO_SUBMISSION_GUIDE.md`](docs/AMO_SUBMISSION_GUIDE.md).

## Disconnect and privacy

- Gmail access uses the `gmail.readonly` scope. OtpPilot does not send, delete or modify mail.
- Message search and code extraction happen locally in the extension background context. No email content or code is sent to an AI service or analytics provider.
- OTPs are held temporarily and cleared on expiry; email bodies are not intentionally stored.
- Firefox keeps its short-lived access token in session memory. To stay connected across restarts, it stores a refresh token and Desktop OAuth client secret in that Firefox profile's extension storage. This storage is not an encrypted vault. Use **Disconnect** to revoke and clear saved sign-in data, especially on a shared computer.
- The optional page helper sends normal `input` and `change` events so framework-controlled forms can notice a fill. The allowlisted website can read the value after it is placed in its form field. The helper never submits the form.

## Troubleshooting

- **Google says the app is not verified:** confirm you trust the OAuth project. While it is in Testing, the Gmail account must be listed as a test user.
- **Google says `invalid_client`:** check that the client ID matches the selected browser and OAuth client type. Chrome uses a Chrome Extension client; Firefox uses a Desktop app client.
- **Google says a client secret is missing (Firefox):** enter the `client_secret` value from the Desktop app credentials file in Firefox Settings and save.
- **Firefox asks to reconnect after several days:** Google may expire refresh tokens after seven days while an external OAuth app requesting Gmail access remains in Testing.
- **No fresh matching code:** check sender, subject phrase, code length, pattern and freshness window. Use a recent message in the configured Gmail account.
- **Inline helper is missing:** add the exact HTTPS hostname in Settings and approve browser site access. The page must have a recognizable OTP field. The email auto-fill only targets blank email-type fields.
- **The website rejects a filled OTP:** ensure the code is still fresh. OtpPilot emits input/change events for the site's form model but never submits the form. For separate digit boxes, copy from the popup.
